# 근거노트 (가칭) — 프로토타입

지문을 넣으면 AI가 국어 문항을 만들고, **정답을 가린 채 다시 풀어 보며 근거와 복수 정답 여부를 검증**하는 서비스의 프로토타입입니다.
선생님이 검토한 문항을 반에 온라인으로 배포하면, 학생이 풀면서 **답을 고른 이유와 확신도**를 남기고, 이 기록으로 선생님용 통계와 학생용 약점 분석을 보여 줍니다.

> 서비스명 "근거노트"는 임시 이름입니다. 정식 출시 전 KIPRIS에서 상표 등록 가능 여부를 확인하세요.

## 빠르게 실행하기

```bash
cd geungeo-note
npm install
cp .env.example .env.local   # 선택: ANTHROPIC_API_KEY를 넣으면 실제 AI 생성·검증이 켜집니다
npm run dev                  # http://localhost:3000
```

- API 키가 없으면 **데모 모드**로 동작합니다. 라이브러리 지문은 미리 검수한 예시 문항을, 직접 등록한 지문은 규칙 기반 문항을 만듭니다.
- 데이터는 `data/db.json`에 저장되고, 처음 실행할 때 데모 데이터가 자동으로 만들어집니다. `npm run seed`로 언제든 초기화할 수 있습니다.

로그인 화면에서 **선생님 또는 학생 카드를 누르면 회원가입 없이 바로 체험**할 수 있습니다. 상단의 "⇄ 역할 바꾸기"를 누르면 다시 계정을 고르는 화면으로 돌아가고, 로그인 화면의 "체험 데이터 초기화"를 누르면 처음 상태로 되돌아갑니다.

아이디로 로그인하려면 아래 계정을 씁니다.

| 데모 계정 | 아이디 | 비밀번호 |
|---|---|---|
| 선생님 | `teacher` | `demo1234` |
| 학생 | `student1` ~ `student5` | `demo1234` |

`student1`(이서준)에게는 아직 풀지 않은 과제가 하나 있어서 문제 풀이 화면을 바로 체험할 수 있습니다. 반 참여 코드는 `KOR2A1`입니다.

실제 운영 시에는 환경 변수 `DEMO_LOGIN=off`로 체험 로그인을 끕니다.

## Firebase App Hosting에 올리기 (체험용)

`apphosting.yaml`에 체험용 설정이 들어 있습니다. 서버를 1대로 고정하고, 데이터를 서버의 임시 폴더에 저장합니다. 그래서 **서버가 한동안 쉬었다가 깨어나거나 새로 배포되면 데모 데이터로 초기화됩니다.**

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고 **Blaze(종량제) 요금제**로 바꿉니다. App Hosting은 Blaze 요금제에서만 쓸 수 있습니다. 예산 알림을 함께 설정해 두세요.
2. 왼쪽 메뉴 **빌드 → App Hosting → 시작하기**를 누릅니다.
3. GitHub 계정을 연결하고 다음을 선택합니다.
   - 저장소: `wndrnxs/ClaudeLab`
   - 앱 루트 디렉터리: `geungeo-note`
   - 라이브 브랜치: `claude/upbeat-cray-wqbvbe` (main에 합친 뒤에는 `main`)
4. 백엔드 이름(예: `geungeo-note`)과 리전을 정하고 **완료 및 배포**를 누릅니다.
5. 빌드가 끝나면 `https://<백엔드이름>--<프로젝트ID>.<리전>.hosted.app` 형태의 주소가 생깁니다. 이후 브랜치에 커밋할 때마다 자동으로 다시 배포됩니다.

실제 AI 생성을 켜려면 Firebase CLI로 비밀값을 등록한 뒤(`firebase apphosting:secrets:set ANTHROPIC_API_KEY`), `apphosting.yaml`의 해당 주석을 풀어 다시 배포합니다.

## 요청사항과 구현 내용

| 요청 | 구현 |
|---|---|
| 수능형 5지선다 | (가)(나) 복합 지문(두 작품 묶기), <보기> 상자 문항, '적절하지 않은 것은?' 발문 섞기, [정답]·[해설]·[오답 풀이] 구성의 해설, 2단 시험지 인쇄(학생용 / 문항 아래 해설 / 맨 뒤 정답·해설) |
| 차별화 포인트·기본 기능 반영 | 지문 근거 하이라이트, 자동 풀이 검증(정답 불일치·복수 정답·근거 미확인 시 "재검토 필요"), 브라우저 안 문항 편집, 문항 하나만 다시 만들기, 평가 요소를 지정한 출제, 반 약점에 맞춘 복습 세트 바로 만들기, 학생용/교사용 인쇄(PDF 저장) |
| 선생님·학생 화면 분리, 온라인 전달 | 역할별 로그인 후 서로 다른 화면(`/teacher`, `/student`). 선생님이 "검토 완료"한 세트를 반에 배포하면 학생의 "내 과제"에 바로 나타나고, 학생은 화면 안에서 풀고 제출 |
| 선생님용 통계 | 과제별 제출 현황, 문항별 정답률, 선지별 선택 인원, **선지마다 학생들이 그 답을 고른 이유**, 확신하고 틀린 학생 수(오개념 신호), 찍어서 맞힌 학생 수, 평가 요소별 정답률, 학생별 결과, AI 오답 이유 분석(오개념 패턴 + 수업 팁) |
| 학생용 약점 분석 | 평가 요소 6개별 정답률(반 평균과 비교), 문학/독서 정답률, 확신도별 정답률, "가장 먼저 보완할 영역"과 공부 방법, 확신하고 틀린 문항을 맨 위에 둔 오답 노트(내가 쓴 이유와 정답 근거를 나란히 비교) |

평가 요소: 사실적 이해, 추론적 이해, 비판적 이해·적용, 표현·구조 파악, 어휘·어법, 감상·해석.

## 디자인 (UI 개선안)

- Figma 시안: [근거노트 — UI 개선안](https://www.figma.com/design/Lln7pJSo9j8DFDHwePiQci). 색·간격·모서리 토큰(변수 26개), 글자 스타일 8개, 버튼·태그 컴포넌트, 선생님 대시보드와 학생 모바일 문제 풀이 화면이 들어 있습니다.
- 코드의 디자인 토큰은 `src/app/globals.css`에 있으며 Figma 변수와 같은 값입니다.
- 방향은 '교무수첩'입니다.
  - 종이색 배경에 잉크 남색 한 가지만 강조색으로 씁니다.
  - 빨강은 오답·재검토에만, 형광펜 노랑은 근거 문장에만 씁니다.
  - 지문·발문·제목은 명조(Noto Serif KR), 화면 글자는 Pretendard를 씁니다.
- 시인성:
  - 가장 작은 글자는 13px, 화면 본문은 15px입니다.
  - 글자 대비는 4.5:1 이상, 버튼 높이는 40px 이상입니다.
  - 키보드로 이동할 때 초점 테두리가 보입니다.
- 선생님 화면은 왼쪽 메뉴, 학생 화면은 상단 탭을 씁니다. 휴대폰에서는 문제를 한 문항씩 풀고 아래 고정 바로 이동합니다.

## 법적 리스크를 줄이기 위해 반영한 것

- **지문 저작권**
  - 기본 라이브러리에는 저작권 보호기간이 끝난 작품(김소월 「진달래꽃」, 윤동주 「서시」)과 직접 쓴 지문만 넣었습니다. 교과서·EBS·모의고사 지문은 넣지 않았습니다.
  - 선생님이 지문을 등록할 때는 권리 근거(직접 작성 / 저작권 만료 / 이용 허락)와 출처를 적고 권리 확인에 동의해야 합니다. 등록한 지문은 그 선생님과 그 선생님의 반에서만 쓰입니다.
  - 인쇄물 하단에 지문 출처와 권리 근거를 자동으로 표기합니다.
- **AI 생성물 검토**: AI가 만든 문항은 선생님이 "검토 완료"를 체크해야 배포할 수 있습니다(서버에서도 확인).
- **개인정보**
  - 이름·아이디·학습 기록만 받고 이메일·전화번호는 받지 않습니다. 가입할 때 수집·이용 동의를 받습니다.
  - 오답 분석을 AI에 맡길 때 학생 이름은 보내지 않고 이유만 보냅니다.
  - 학생은 본인 반 과제만, 선생님은 본인 반 학생만 볼 수 있습니다.
- **정답 노출 방지**: 학생이 제출하기 전에는 정답·해설·근거를 브라우저로 보내지 않습니다.
- **경쟁 서비스와의 구분**: 이름, 색(청록 계열), 문구, 크레딧 명칭, 출제 유형 코드 체계를 따라 하지 않았습니다.

## AI 문항 생성 파이프라인 (`src/lib/ai/`)

1. **생성**: Claude가 구조화 출력(JSON 스키마)으로 발문·선지·정답·선지별 근거·해설·근거 문장·평가 요소·난이도를 만듭니다.
2. **형식 검사**: 선지 개수, 정답 번호 범위, 선지별 근거 개수를 확인합니다.
3. **근거 대조**: AI가 인용한 근거 문장이 지문에 실제로 있는지 코드로 한 글자씩 대조합니다(공백·줄바꿈 차이는 허용).
4. **풀이 검증**: 정답을 숨긴 채 Claude가 문항을 다시 풀고, 다른 답을 고르거나 정답으로 볼 여지가 있는 선지를 찾으면 "재검토 필요"로 표시합니다.

- 기본 모델: `claude-opus-5-5`(`CLAUDE_MODEL`로 변경 가능)
- 설정:
  - 생성은 effort `high`, 검증과 오답 분석은 effort `medium`으로 호출합니다.
  - 시스템 프롬프트에 프롬프트 캐시를 적용했습니다.
  - 안전 분류기가 요청을 거절할 때를 대비해 서버 측 대체 모델(`fallbacks: "default"`, 베타 `server-side-fallback-2026-07-01`)을 켜 두었습니다. 원하지 않으면 `src/lib/ai/claude.ts`에서 끄면 됩니다.
- API 키는 서버에서만 읽습니다.

## 구조

```
src/
  app/
    login, signup            로그인·회원가입
    teacher/                 선생님: 대시보드, 지문, 문항 만들기, 세트 편집기, 인쇄, 과제 통계, 반, 학생별 분석
    student/                 학생: 내 과제, 문제 풀기/결과, 약점 분석
    api/                     로그인, 반, 지문, 문항 세트(생성·수정·재검증·다시 만들기), 과제(배포·제출·오답 분석)
  lib/
    ai/                      Claude 호출, 프롬프트, 스키마, 데모 생성기, 생성·검증 파이프라인
    analytics.ts             과제 통계·학생 약점 분석 계산
    evidence.ts              근거 문장 대조·하이라이트
    library.ts               기본 지문 라이브러리와 검수된 예시 문항
    seed.ts                  데모 데이터
    db.ts                    JSON 파일 저장소(운영 시 DB로 교체)
tests/                       단위 테스트(vitest)
```

## 확인 방법

```bash
npm test          # 단위 테스트
npm run typecheck # 타입 검사
npm run build     # 프로덕션 빌드
```

## 한계와 다음 단계

- **실제 Claude API 경로는 API 키 없이 개발해 타입 검사까지만 했습니다.** 키를 넣고 몇 개 지문으로 생성·검증 품질과 1회당 비용을 먼저 측정하세요.
- 저장소가 JSON 파일 하나라서 동시 사용자가 많으면 맞지 않습니다. 운영 전에 PostgreSQL 등으로 바꿔야 합니다(`src/lib/db.ts`만 교체하면 됩니다).
- 아직 없는 기능:
  - HWPX 내보내기
  - 서술형 문항
  - OCR
  - 비밀번호 찾기
  - 만 14세 미만 보호자 동의 절차
  - 이용약관·개인정보처리방침 페이지
- AI 생성은 1~2분 걸릴 수 있습니다. 운영 시에는 백그라운드 작업과 진행 상황 알림으로 바꾸는 것이 좋습니다.
- 출시 전에 IT·저작권 전문 변호사의 검토를 받으세요.
